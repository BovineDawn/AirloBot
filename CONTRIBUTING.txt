AIRLOBOT DEVELOPMENT AND VERSION CONTROL

Repository: https://github.com/BovineDawn/AirloBot

Use short-lived feat/, fix/ or docs/ branches from main. Keep commits scoped to
one reviewable change. Open a pull request with the problem, resulting behavior,
validation and any migration impact. Avoid force pushes to shared branches.

Local checks (Node 22.23.4 used here)
  npm ci
  npm test
  npm run privacy:check
  npm run build
  git diff --check
On a clean Windows installation, run npx install-electron and
npm run runtime:install before npm start. The app manages the bundled engine.
Live tests require the bundled runtime and an explicit local GGUF path:
  npm run test:live -- "D:\Models\model.gguf"
  npm run test:agents -- "D:\Models\model.gguf"
  node scripts/import-smoke.mjs "D:\Models\model.gguf"
The chat smoke test is offline unless --downloads is also supplied. That flag
explicitly enables public Hugging Face search/download checks. These tests use
ignored test-results profiles and do not run in public CI.

Keep package-lock.json committed. Change version in both package files together.
Tag reviewed working milestones with annotated vX.Y.Z tags. Prefer focused PRs
for the tool loop, task persistence, delegation, and UI; do not introduce them
as one enormous change. Any new execution capability needs tests for its actual
failure modes, permission boundaries and cancellation behavior.

Do not commit data/, release/, node_modules/, test-results/, model weights,
.env files, private keys, original extracted Grok Bot files or credentials.
The Git root is this app folder, never the parent research workspace.
Model weights stay user-supplied. Native engine binaries are bundled with
desktop packages from the pinned runtime lock, never committed to Git.

CI runs isolated unit tests and a renderer production build on Windows/Linux.
The Windows desktop package is validated locally. CI does not imply GUI or real
model evaluation. Before distribution, verify ASAR contents exclude user data
and research artifacts, and test the packaged launcher on Windows.

README product images live under docs/media and use synthetic fixtures only.
Recreate them with npm run build, then:
  npx --no-install electron scripts/capture-readme.cjs
Inspect every image before publishing. Do not substitute real conversations or
user project captures. See docs/media/README.md for provenance and constraints.

Main branch rules (configured on GitHub on 2026-11-01)
https://github.com/BovineDawn/AirloBot/rules/26319654
All changes require a pull request, resolved review threads, and an up-to-date
branch with successful GitHub Actions checks named verify (ubuntu-latest) and
verify (windows-latest). Keep these job names aligned with the ruleset.
Force pushes and deletion are blocked. Squash or rebase merges preserve linear
history. No actors, including administrators, have bypass permission.
The solo-maintainer policy requires zero additional human approvals; the owner
can merge their own PR once all checks pass. Revisit this when adding reviewers.
These rules are configured on GitHub; the workflow file alone cannot enforce
them. Select a project license before describing this repository as licensed
open source.

Baseline: v0.1.0 preserves the original working prototype.
v0.2.0: AirloBot name, robot branding and neutral appearance options.

v0.3.0: Project tools, bounded local helpers, task history and reviewed file proposals.
For current standalone behavior, test:agents and test:standalone share the same
acceptance test. Run npm run test:standalone -- <local-GGUF-path>. It creates only disposable
files under ignored test-results; do not run it against user projects.

v0.4.0: Focus workspace, saved drafts, longer replies and three accessible themes.
Run the manual renderer and local response checks described in
docs/FOCUS_RELEASE_NOTES.txt. They do not run in public CI.

v0.5.0: Configurable task turns/time, recent-task deletion, Ask mode context, and
repository privacy checks. Enable the versioned pre-push hook in every clone:
  git config core.hooksPath .githooks
See docs/TASK_CONTROLS_AND_PRIVACY.txt for semantics and test coverage. Never
force-add saved conversations or bypass a privacy failure to publish.

v0.6.0: Bundled authenticated llama.cpp, direct GGUF registration, persistent
project conversations, paged file browsing, reviewed folders and targeted edits,
and conflict-aware undo. Native binaries live only in ignored native/ and release/.
Run scripts/focus-ui-test.cjs with Electron for synthetic renderer checks.

v0.7.0: Optional in-memory hardware snapshots, conservative model-fit labels,
bounded remote GGUF metadata previews, and a simpler download chooser.
Run the new synthetic UI checks after building:
  npx --no-install electron scripts/library-ui-test.cjs
Optional hardware smoke test (prints only validation outcomes):
  node scripts/hardware-live-test.mjs
Add --hub only when explicitly testing a small public model download. All live
test state remains in ignored test-results. Never commit real device reports.
Snapshots must remain outside persisted app state and outbound Hub requests.

v0.8.0: Catalog popularity/update/file-size metrics, page-level memory comparison,
visible device guidance, checked variant suggestions, and Settings category panels.
The library UI test covers category draft retention and all three themes; captures
force a repaint before saving. All fixtures and product images remain synthetic.

v0.8.1: Project creation recovery, grounded continuation context, pending folder
support across turns, actionable directory/missing-file reads, and chat following.
Run npm run test:project-build -- <local-GGUF-path> for a natural-language folder
then Python GUI calculator request. It uses an isolated offline service, verifies
that the model does not write, then explicitly applies disposable test proposals.
It tests file creation, not generated code quality. Review generated source before
running it; Python GUI execution and arithmetic checks are separate acceptance steps.
The Focus renderer test covers streaming, scroll-up preservation, Jump to latest,
late layout and resizing. Runtime state and generated examples stay in test-results.

0.8.1 acceptance (Windows, 2026-11-01): 59 unit tests and the Focus renderer suite
passed. A local Gemma run completed the exact natural-language folder/calculator
sequence with real proposals and explicit reviewed writes. The generated calculator
needed agent follow-ups to fix a Tkinter startup error; the repaired program passed
button-driven arithmetic, decimal, precedence, clear, zero-division, grid overlap,
and AST-call rejection checks. Generated-code correctness is still model-dependent.
The packaged ASAR was checked against source and audited for excluded runtime data.
