AIRLOBOT DEVELOPMENT AND VERSION CONTROL

Repository: https://github.com/BovineDawn/AirloBot

Use short-lived feat/, fix/ or docs/ branches from main. Keep commits scoped to
one reviewable change. Open a pull request with the problem, resulting behavior,
validation and any migration impact. Avoid force pushes to shared branches.

Local checks (Node 22.23.4 used here)
  npm ci
  npm test
  npm run build
  git diff --check
On a clean Windows installation, run npx install-electron before npm start.
Live model/download/import smoke tests require the local runtime and explicit
network/disk setup; they do not run in public CI.

Keep package-lock.json committed. Change version in both package files together.
Tag reviewed working milestones with annotated vX.Y.Z tags. Prefer focused PRs
for the tool loop, task persistence, delegation, and UI; do not introduce them
as one enormous change. Any new execution capability needs tests for its actual
failure modes, permission boundaries and cancellation behavior.

Do not commit data/, release/, node_modules/, test-results/, model weights,
.env files, private keys, original extracted Grok Bot files or credentials.
The Git root is this app folder, never the parent research workspace.
A model or local integration should be an optional user-installed dependency,
not a binary embedded in the Git repository.

CI runs isolated unit tests and a renderer production build on Windows/Linux.
The Windows desktop package is validated locally. CI does not imply GUI or real
model evaluation. Before distribution, verify ASAR contents exclude user data
and research artifacts, and test the packaged launcher on Windows.

Recommended repository settings (must be configured on GitHub)
Require a pull request and successful CI on main; disallow force pushes and
branch deletion; use branch protections/rulesets appropriate to your account.
A workflow file alone does not configure these policies. Select a project
license before describing this repository as licensed open source.

Baseline: v0.1.0 preserves the original working prototype.
v0.2.0: AirloBot name, robot branding and neutral appearance options.
